# pair-wise-yf-55 动态表单规则编排和版本迁移模拟器

## 源提示词摘要
业务人员拖拽字段、设置分组、联动条件、计算规则、必填逻辑和多语言文案；发布前模拟旧数据在新结构下的迁移。系统比较版本差异，警告失效规则、循环依赖和引用删除，同时按历史版本解释过去提交的数据。

## 技术栈
React 19 + TypeScript + Vite + MUI + Redux Toolkit + React Hook Form + i18next + dnd-kit。

## 已实现闭环
- 字段拖拽排序、新增字段、切换必填、添加联动规则；草稿与正式版本分离，历史版本冻结只读。
- 新旧版本差异（新增/删除字段、新增规则）。
- **可续作的迁移账**（`src/migration/engine.ts` + `src/store.ts`）：
  - **发布生成待迁批次**：发布新版本时按容量（每批 2 条）切出批次，只含从未迁入过的快照；每批冻结发布时刻的字段与规则副本。
  - **按当前规则校验必填与联动**：`validateSnapshot` 检查静态必填及 `equals/notEmpty → require/show` 联动；阻塞项挂起并给出缺口，`show` 不满足仅作信息提示。
  - **容量满了排队**：前序批次未完成时，后续批次不能领取容量（界面禁用执行按钮）。
  - **失败从断点恢复**：批次保存 `checkpoint`（已连续写入条数），中断后续作跳过已写项；提供「模拟执行中断」按钮演示。
  - **重试不重复写入**：所有写入走统一写入流水 `journal`，以 `snapshotId + targetVersionId` 幂等去重；项上保存快照内容指纹，重试期间数据被改动会先按冻结规则重校验。
  - **补齐后续作**：阻塞快照可在界面补齐字段，按批次冻结规则重新校验后从断点继续。
  - **新版本再发布**：排队/阻塞/失败/执行中的批次一律作废（void 并写明原因），按新版本重算批次；已完成批次与流水不动，每条流水永久标注解释版本，历史数据始终按写入时版本解释。
- 运行态动态表单按当前正式版本实时计算显隐与联动必填。
- localStorage 持久化（含旧持久化结构的兼容补齐）。

## 目录
- `src/migration/engine.ts`：迁移账领域模型与纯函数（校验、投影、指纹、进度）。
- `src/store.ts`：计划/批次/流水状态机（发布切批、执行、断点恢复、补齐重校验、作废重算）。
- `scripts/migration-check.mjs`：无头逻辑断言脚本，覆盖排队、阻塞、断点、幂等、作废重算与版本冻结解释。

## 启动与验证

```bash
npm install
npm run dev                       # 开发端口 62020
npm run build                     # 类型检查 + 生产构建
node scripts/migration-check.mjs  # 迁移账核心保证的无头断言
```
